# Bucketing specification

Normative. Every SDK must produce byte-identical results. Divergence is a CI failure,
not a rounding difference.

## Algorithm

```
input   = flagKey + ":" + salt + ":" + bucketKey     // UTF-8, no normalisation
hash    = MurmurHash3_x86_32(input, seed = 0)        // returns uint32
bucket  = hash % 100000                              // [0, 100000)
```

`bucketKey` is the value of the flag's `bucketBy` attribute, stringified. If the attribute
is absent, the flag serves its default variation and no bucket is computed.

## Rules that are easy to get wrong

- **Unsigned arithmetic.** MurmurHash3 returns a `uint32`. Languages without unsigned
  integers (Java, and JavaScript's bitwise ops) must mask to 32 bits before the modulo,
  or negative values will silently shift the bucket.
- **UTF-8 bytes, not code units.** Hash the UTF-8 encoding of the joined string. A
  JavaScript SDK hashing UTF-16 code units will diverge from Go on any non-ASCII key.
- **The separator is `:`** and is never escaped. Keys are restricted to
  `[a-zA-Z0-9._-]` at write time so the join stays unambiguous.
- **Seed is 0** everywhere.

## Rollout assignment

Given a rollout whose weights sum to 100000, walk the distribution in declaration order
accumulating weights and serve the first variation whose cumulative weight exceeds
`bucket`. Declaration order is part of the contract: it is what makes raising a rollout
from 10% to 20% additive, so nobody already inside the rollout moves.

## Conformance

`spec/conformance/bucketing.json` holds the shared fixture. Each SDK runs it in CI as a
required check.

```json
{
  "version": 1,
  "cases": [
    { "flagKey": "...", "salt": "...", "bucketKey": "...", "expectedBucket": 0 }
  ]
}
```

The fixture is generated by the reference implementation and committed. Regenerating it
is a deliberate, reviewed act — never a way to make a failing SDK pass.
